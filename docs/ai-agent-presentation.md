# YW Coder AI Agent 项目介绍材料

> 面向内部/客户介绍：YW Coder 是什么、AI Agent 怎么用、如何在代码研发全流程提效

---

## 1. 项目定位（30 秒）

**YW Coder = VS Code 扩展 + AI Agent，让开发者在 IDE 里用自然语言驱动整个研发流程。**

- 基于 **Claude Agent SDK** 构建
- 支持 **VS Code 桌面端** 和 **VS Code Web** 两种部署方式
- AI 推理和工具执行由本地 CLI 完成，插件负责 UI、进程管理和文件系统桥接
- 所有代码上下文、文件操作、命令执行都在当前 workspace 内进行

### 一句话价值

> 把 Claude 从"聊天机器人"变成"驻场程序员"：理解代码库、改代码、跑命令、写测试、出文档，全程在 IDE 内闭环。

---

## 2. 系统架构（1 分钟）

```
┌─────────────────────────────────────────┐
│           Webview UI (Vue)              │
│     聊天界面 / 模式选择 / 附件 / 设置      │
└─────────────┬───────────────────────────┘
              │ VS Code webview message
┌─────────────▼───────────────────────────┐
│        Extension Host (Node.js)         │
│   AIAgentService 管理会话和 CLI 进程      │
│   AISdkService 封装 Claude Agent SDK     │
└─────────────┬───────────────────────────┘
              │ stdin/stdout
┌─────────────▼───────────────────────────┐
│         本地 YwCoder CLI                │
│   基于 @anthropic-ai/claude-agent-sdk    │
│   执行推理、读写文件、调用工具、MCP 等    │
└─────────────────────────────────────────┘
```

### 关键映射

- Webview 一个 **Session** = 一个聊天标签页
- Extension Host 一个 **Channel** = 一个 CLI 进程
- `sessionId` 用于恢复对话上下文，`channelId` 用于关联当前进程

## 3. AI Agent 核心能力（2 分钟）

### 3.1 代码理解

- 读取整个代码库，回答"这个项目是做什么的"
- 分析单个文件/函数/类的逻辑
- 根据选中代码回答具体问题

### 3.2 代码生成与编辑

- 根据需求生成新文件、新函数
- 多文件联合修改（MultiEdit）
- 自动重构、重命名、补全边界情况
- 支持图片、PDF、文本附件作为上下文

### 3.3 命令执行

- 在终端运行测试、构建、lint、git 等命令
- 读取命令输出，根据结果继续迭代
- 自动处理命令失败场景

### 3.4 规划与任务拆解

- `plan` 模式：只输出方案，不实际执行
- `TodoWrite` 工具：把大任务拆成可勾选的小任务
- 适合复杂需求的前期设计

### 3.5 MCP 扩展

- 通过 MCP（Model Context Protocol）连接外部工具
- 可接入数据库、API、知识库、内部平台等

## 4. 权限模式：从"完全手动"到"完全自动"（1 分钟）

YW Coder 提供 4 种权限模式，适应不同信任场景：

| 模式 | 行为 | 适用场景 |
|---|---|---|
| **default** | 每次工具调用都弹窗确认 | 陌生任务、关键代码 |
| **acceptEdits** | 自动接受文件编辑，其他仍询问 | 日常编码 |
| **plan** | 只规划不执行 | 方案设计 |
| **bypassPermissions** | 自动接受所有权限请求 | 充分信任、批量重构 |

### 切换方式

- 点击聊天输入框左侧模式下拉
- 快捷键 `Shift + Tab` 循环切换
- 设置页也可配置默认模式

> 强调：bypassPermissions 会跳过所有确认，适合在沙盒或测试环境使用。

## 5. 代码研发全流程提效（5 分钟）

### 5.1 需求分析 → 技术方案

**场景**：产品经理丢过来一句话需求，需要评估实现方案。

**用法**：

```text
帮我分析一下，如果要在现有用户系统里加入 OAuth2 登录，需要改哪些模块？先只给方案，不要改代码。
```

**提效点**：

- 快速梳理代码库结构
- 自动识别受影响的文件和接口
- 输出可执行的步骤清单（TodoWrite）

---

### 5.2 编码实现

**场景**：需要新增一个 REST API。

**用法**：

```text
在 src/routes/ 下新增一个 /api/orders 的 GET 接口，返回订单列表，数据从现有的 OrderService 取。
```

**提效点**：

- 自动生成路由、控制器、DTO
- 自动处理错误码、日志、类型定义
- 自动关联现有服务，避免重复造轮子

---

### 5.3 代码重构

**场景**：旧代码耦合严重，需要拆分。

**用法**：

```text
把 UserController 里的登录逻辑拆成一个独立的 AuthService，并更新所有引用。
```

**提效点**：

- 跨文件自动修改引用
- 保持类型正确
- 自动跑编译/测试验证

---

### 5.4 调试排错

**场景**：测试报错，需要定位根因。

**用法**：

```text
运行 npm test 报错，帮我看看是哪里引起的。
```

**提效点**：

- 自动读取错误日志和堆栈
- 定位到具体文件和行号
- 给出修复建议并自动应用

---

### 5.5 生成测试

**场景**：新写了业务逻辑，需要补测试。

**用法**：

```text
为 src/services/order.ts 里的 createOrder 函数生成单元测试，覆盖正常和异常分支。
```

**提效点**：

- 自动生成测试用例
- 自动 mock 依赖
- 运行测试并修复失败用例

---

### 5.6 代码审查

**场景**：提交前想先自查一遍。

**用法**：

```text
 review 一下当前改动的代码，看看有没有潜在问题。
```

**提效点**：

- 发现空指针、资源泄漏、并发问题
- 检查是否符合项目规范
- 给出优化建议

---

### 5.7 文档与注释

**场景**：代码缺少注释，README 过期。

**用法**：

```text
给 src/utils/formatter.ts 里的函数加上 JSDoc 注释，并更新 README 里的使用示例。
```

**提效点**：

- 自动生成准确注释
- 同步更新文档
- 保持中英文一致

## 6. 实用操作技巧（2 分钟）

### 6.1 选中代码作为上下文

在编辑器里选中一段代码再输入问题，YW Coder 会自动把选区作为 `<ide_selection>` 上下文发送。

### 6.2 /model 切换模型

```text
/model
```

快速切换当前会话使用的模型（Claude Opus / Sonnet / Haiku 等）。

### 6.3 /btw 追加追问

当 AI 正在回复时，可以输入：

```text
/btw 顺便把刚才那个函数也加上异常处理
```

不用等回复完就能追加要求。

### 6.4 附件

支持拖拽图片、PDF、文本文件到输入框，作为问题上下文。

### 6.5 会话管理

- 多标签页并行对话
- 历史会话列表
- 刷新页面后模式和模型选择会持久化（基于 extension globalState）

## 7. 部署方式（1 分钟）

### 桌面端

- 安装 VS Code 扩展
- 插件自动查找或内置 YwCoder CLI
- 本地运行，代码不离开本机

### Web 端

- 打包 `vscode/dist/ywcoder-web-*`
- 部署到服务器，通过浏览器访问
- 适合云端开发环境、内网统一入口
- 扩展和 CLI 在服务器端运行

---

## 8. 安全与合规要点（1 分钟）

- **本地执行**：CLI 在本地/服务器运行，代码不会被上传到第三方
- **权限可控**：4 种权限模式，从完全手动到完全自动
- **审计友好**：所有工具调用都可被拦截和记录
- **模型隔离**：支持切换不同模型，敏感项目可用私有化部署

## 10. 一句话收尾

> YW Coder 不是替代程序员，而是把重复、机械、上下文切换多的工作交给 AI，让开发者把精力集中在架构设计和关键决策上。
